# KIN Care Management

ระบบบริหารงานดูแลผู้สูงอายุของ KIN Rehabilitation & Homecare: ระบบจัดการสำหรับผู้บริหารและผู้จัดการสาขา, KinApp สำหรับทีมดูแล, แอปจัดยาสำหรับห้องยา และหน้าสำหรับครอบครัวของผู้รับบริการ

เว็บจริง: https://nursing-home-kin.vercel.app

## แอปและหน้าเว็บ

| ที่อยู่ | ใช้โดย | ทำอะไร |
|---|---|---|
| `/` | ผู้บริหาร, ผู้จัดการสาขา, หัวหน้าพยาบาล, แคชเชียร์ | ระบบจัดการ: ผู้รับบริการ ห้อง งานประจำวัน ตารางเวร สุขภาพ ใบเสนอราคา สัญญา การเงิน ภาพรวมและรายงาน สาขา ทีม รีวิว KPI ประวัติการใช้งาน |
| `/staff` | ทีมดูแล (ติดตั้งเป็นแอปบนมือถือได้) | KinApp: เช็คชื่อด้วยรูป งานวันนี้ จ่ายยา สัญญาณชีพ ส่งเวร ผลงานทีม |
| `/pharmacy` | ห้องยา | รับยาเข้าคลัง จัดยาลงซอง ตรวจ QA รายงานการจัดยา |
| `/survey?branch=…` | ครอบครัว (ไม่ต้องเข้าสู่ระบบ) | ประเมินความพึงพอใจ / แจ้งเรื่องร้องเรียนถึงสาขา |
| `/family/{รหัส}` | ครอบครัว (ไม่ต้องเข้าสู่ระบบ) | สมุดภาพประจำวัน: รูปและบันทึกการดูแล การให้ยาตามมื้อ |
| `/review/{รหัส}` | ครอบครัว (ไม่ต้องเข้าสู่ระบบ) | รีวิวพนักงานที่ดูแล (เลือกได้หลายคน) |

## สิทธิ์การใช้งาน

| ตำแหน่ง | สิทธิ์เริ่มต้น | เห็นข้อมูล |
|---|---|---|
| **Global Admin** (ผู้บริหาร) | ทุกเมนู | ทุกสาขา · แก้ข้อมูลสาขา น้ำหนัก KPI และข้อมูลส่วนกลางได้ |
| **Branch Admin** (ผู้จัดการสาขา) | ทุกเมนู · สร้างบัญชีและกำหนดสิทธิ์พนักงานในสาขา · อนุมัติคอร์สกายภาพฟรี | เฉพาะสาขาตัวเอง |
| **Head Nurse** (หัวหน้าพยาบาล) | งานดูแล ห้องและย้ายห้อง ตรวจงาน ใบเสนอราคา KinApp แอปจัดยา · ขายคอร์สกายภาพ | เฉพาะสาขาตัวเอง |
| **Cashier** (แคชเชียร์) | สัญญา การเงิน ห้องว่าง | เฉพาะสาขาตัวเอง |
| **Nurse** (ทีมดูแล / ห้องยา) | KinApp และแอปจัดยา | เฉพาะสาขาตัวเอง · KPI เห็นรายละเอียดเฉพาะของตัวเอง |

สิทธิ์ติ๊กเพิ่ม/เอาออกรายคนได้ในหน้า "ทีมและสิทธิ์การใช้งาน" (ค่าเริ่มต้นอยู่ใน `lib/perms.ts`) · การแยกสาขาบังคับที่ server ทุก API ไม่ได้ซ่อนแค่หน้าจอ · ทุกการเพิ่ม/แก้/ลบ และการเข้าสู่ระบบบันทึกในหน้า "ประวัติการใช้งาน"

## ระบบหลัก

- **ผู้รับบริการ** ทะเบียน ประวัติรายบุคคล (กราฟสัญญาณชีพ ยา นัดหมาย งานดูแล) และลิงก์ครอบครัว
- **มอบหมายและตรวจงาน** มอบหมายจากแม่แบบงานมาตรฐาน ตั้งเป็นงานประจำ (ระบบสร้างให้ทุกวัน) ระบุผู้รับผิดชอบจากตารางเวร พนักงานส่งงานพร้อมรูปที่ประทับวันเวลา ผู้จัดการตรวจและให้ดาว
- **ตารางเวร** ปฏิทินเวรเช้า 07:00–19:00 / ดึก 19:00–07:00 · พนักงานเช็คชื่อเข้า-ออกด้วยรูปถ่ายสดจากกล้อง เวลาใช้ของ server มาสายเกิน 15 นาทีบันทึกเป็นสาย
- **สัญญาณชีพและแจ้งเตือน** ค่าเกินเกณฑ์ (`lib/vitals.ts`) สร้างแจ้งเตือนให้หัวหน้าพยาบาลรับทราบพร้อมบันทึกการดูแล
- **ยา (MAR)** ห้องยาจัดซองและตรวจ QA → ขึ้นคิวจ่ายยาใน KinApp → บันทึกผู้ให้ยาและเวลา
- **เสียงจากครอบครัว** QR / ลิงก์ของแต่ละสาขา และป้ายตั้งโต๊ะ A4 · ผลประเมินและเรื่องร้องเรียนเข้าระบบทันที
- **ลิงก์ครอบครัว** 1 ลิงก์ต่อผู้รับบริการ (รหัสสุ่ม ใช้ได้ 90 วัน ยกเลิกได้) เปิดสมุดภาพประจำวันและรีวิวพนักงาน · รูปขึ้นให้ญาติเฉพาะที่พนักงานติ๊กแชร์ ผู้จัดการซ่อนภายหลังได้
- **KPI พนักงาน** รายเดือน 4 ส่วน แต่ละส่วน 0–100 รวมตามน้ำหนัก (ค่าเริ่มต้น): ดาวจากครอบครัว 40% · ดาวจากผู้จัดการ 30% · งานที่ส่ง 20% · มาตรงเวลา 10% · ส่วนที่ยังไม่มีข้อมูลไม่นับและเกลี่ยน้ำหนักที่เหลือ (`lib/kpi.ts`)
- **ใบเสนอราคา → สัญญา** เลือกบริการจากใบราคา (`lib/priceList.ts`) ส่งต่อเป็นสัญญาได้ · เปิดสัญญา 3 ขั้น: รายละเอียด → ค่าใช้จ่าย → เลือกห้อง (เตือนเมื่อประเภทห้องไม่ตรงกับค่าห้อง)
- **การเงิน** ใบแจ้งหนี้ / ใบเสร็จรับเงิน / ใบกำกับภาษี รับชำระหลายงวด แนบสลิป · กฎการคิดเงินดูหัวข้อ "กฎการคิดเงิน" ด้านล่าง
- **คอร์สกายภาพ** ขายคอร์สแล้วนักกายภาพตัดครั้งพร้อม Progress note · เหลือ 2 ครั้งเตือนให้แจ้งญาติ
- **คลังยาและเวชภัณฑ์** เบิกให้ผู้รับบริการแล้วค้างเป็นรายการรอเรียกเก็บในหน้าการเงิน
- **D/C กลับบ้าน** ปิดสัญญา คืนห้อง พิมพ์ใบจำหน่าย พร้อมสรุปคืนเงินประกัน
- **ภาพรวมและรายงาน** แดชบอร์ดแยกแท็บ ภาพรวม / การเงิน / การเข้าพัก / คุณภาพการดูแล / กายภาพ
- **พิมพ์เอกสาร** ทุกหน้าต่างพิมพ์เป็น A4 พร้อมหัวกระดาษบริษัท · ใบเสร็จพิมพ์หน้าเดียวไม่มีหัว-ท้ายของเบราว์เซอร์

## กฎการคิดเงิน

| เรื่อง | กฎ | โค้ด |
|---|---|---|
| VAT ค่าห้อง | บวกเพิ่มจากราคาค่าห้องเต็ม (ค่าเริ่มต้น 7% แก้อัตราได้ หรือเอาติ๊กออก = ไม่คิด VAT) · รายการบริการอื่นไม่มี VAT · ใบเก่าเก็บอัตราเดิมไว้ในบรรทัด | `lib/billing.ts` `vatOf` |
| ส่วนลด | ต่อบรรทัด เป็นบาทหรือ % · ลดก่อนคิด VAT | `lineDiscount` |
| มัดจำห้องตอนจอง | **ไม่ใช่ส่วนลด** หักเป็น "เงินที่รับไว้แล้ว" หลังรวม VAT (บรรทัด `credit`) | `totals`, `creditOf` |
| ใบแรกเข้าจากสัญญา | ค่าบริการ × จำนวนเดือนที่เลือกชำระล่วงหน้า + เงินประกัน − มัดจำห้อง · เลือกล่วงหน้า = สถานะค้างชำระ · ไม่เลือก = รอตรวจสอบยอด | `components/views/Billing.tsx` `contractStartLines`, `contractInvoice` |
| ใบรอตรวจสอบยอด | การเงินกด "ยืนยันยอด" ก่อนจึงรับชำระได้ | สถานะ `DRAFT` |
| ครบรอบบิลรายเดือน | สัญญาใช้งานอยู่ที่ยังไม่มีใบเดือนนี้ ขึ้นในหน้าการเงิน สร้างเป็นใบรอตรวจสอบยอดได้ทีเดียว | `due`, `makeDue` |
| คอร์สกายภาพ | ต้องซื้อคอร์สก่อนบันทึกกายภาพ · คอร์สที่มีราคาต้องออกใบแจ้งหนี้ก่อนใช้ · คอร์สฟรีต้องเป็นผู้จัดการพร้อมเหตุผล | `app/api/clinic/route.ts` |
| D/C | เตือนรายการที่ยังไม่เรียกเก็บ (ยา เวชภัณฑ์ คอร์ส) · คืนเงินประกัน = เงินประกันที่รับจริง − ค้างชำระ − ยังไม่เรียกเก็บ | `dcRefund` |
- **ใช้งานออฟไลน์ (KinApp / แอปจัดยา)** บันทึกไว้ในเครื่องแล้วส่งเมื่อกลับมาออนไลน์ (`lib/store.ts`, `public/sw.js`)

## เริ่มต้นพัฒนา

ต้องมี Node.js 20+ และฐานข้อมูล PostgreSQL (ตอนนี้ใช้ Neon)

```bash
npm install
cp .env.example .env.local      # แล้วใส่ DATABASE_URL
npm run db:setup                # สร้าง/อัปเดตตาราง (รันซ้ำได้ ไม่ลบข้อมูล) และบัญชีทดลอง
npm run dev                     # http://localhost:3000
```

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run dev` | เปิดระบบบนเครื่อง |
| `npm run build` | build สำหรับใช้งานจริง |
| `npm run lint` | ตรวจ TypeScript |
| `npm run db:setup` | สร้างหรืออัปเดตตารางตาม `db/schema.sql` |

เมื่อเพิ่มตารางหรือคอลัมน์ใน `db/schema.sql` ให้รัน `npm run db:setup` กับฐานข้อมูลที่ใช้งาน (เขียนแบบ `IF NOT EXISTS` รันซ้ำได้)

> **ระวัง: ตอนนี้เครื่องพัฒนากับเว็บจริงใช้ฐานข้อมูลเดียวกัน** ทุกอย่างที่บันทึกบน localhost (สัญญา ใบแจ้งหนี้ ผู้รับบริการ) เข้าเว็บจริงทันที
> - ทดสอบหน้าจอได้ แต่อย่ากดบันทึกสัญญา/ใบแจ้งหนี้ทดลอง (เลข HN และเลขเอกสารเป็นลำดับ ลบแล้วเลขข้าม)
> - ถ้าต้องสร้างข้อมูลทดสอบ ลบด้วย id ที่สร้างเท่านั้น ห้ามลบตามช่วงเวลา
> - อย่ารัน `next build` หรือลบ `.next` ขณะ `npm run dev` เปิดอยู่ (dev server พัง) ให้ build ในโฟลเดอร์สำเนาแทน

## ค่าที่ต้องตั้ง (Environment variables)

| ชื่อ | จำเป็น | ความหมาย |
|---|---|---|
| `DATABASE_URL` | ใช่ | connection string ของ PostgreSQL · ห้าม commit (`.env.local` อยู่ใน `.gitignore`) |
| `NEXT_PUBLIC_SITE_URL` | ไม่ | ที่อยู่เว็บจริงที่ใช้ในลิงก์และ QR ที่ส่งให้ญาติ (ค่าเริ่มต้น `https://nursing-home-kin.vercel.app`) |
| `NEXT_PUBLIC_SHOW_DEMO_ACCOUNTS` | ไม่ | `false` = ซ่อนบัญชีทดลองในหน้าเข้าสู่ระบบ (**ต้องตั้งก่อนใช้งานจริง**) |
| `SEED_DEMO` | ไม่ | `false` = `db:setup` ไม่สร้างบัญชีทดลอง |
| `AUTO_APPROVE_SIGNUP` | ไม่ | `true` = สมัครเองแล้วเข้าได้ทันที ไม่ต้องรออนุมัติ |

## Deploy

เชื่อม repository กับ Vercel แล้วตั้ง `DATABASE_URL` ใน Project Settings → Environment Variables · push ขึ้น `main` แล้ว Vercel deploy ให้เอง
ระบบบนเครื่องกับเว็บจริงใช้ฐานข้อมูลเดียวกันได้ (ลิงก์ครอบครัวที่สร้างจากเครื่องเปิดบนเว็บจริงได้)
